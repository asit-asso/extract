The archiving plugin saves the processing results of a request item in a directory. Specify a path (local or network) where the files will be archived.

The archive directory can be local or on the company network. Path examples:

  • Local Windows directory: D:\extract_data\...
  • Local Linux directory: /var/extract_data\...
  • Windows network directory (UNC): \\server\share\folder...

The archive path can contain variables that will be replaced by request properties. The allowed dynamic properties are the following:

  • orderLabel
  • orderGuid
  • productGuid
  • productLabel
  • startDate
  • organism
  • client

Archive path example: /var/extraction/{orderLabel}-{orderGuid}/{productGuid}/

If the archive path is accessible to operators through a URL, it can be entered in the "Operator URL" field. The URL can contain the same variables as the archive path. If a URL is entered, it is displayed in the request details instead of the archive path.

Important:

  • If the target directory exists and contains files with the same names as the files to archive, they will be overwritten.
  • If the Extract application is deployed on a Linux environment, archiving to a Windows network directory will not be possible.
  • If you want to archive to a shared Linux directory, make sure the Samba mount has been completed beforehand.
  • The Tomcat user must have sufficient permissions to write to the specified network directory.
